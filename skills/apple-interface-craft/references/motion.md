# Apple 动效

Apple 动效不是在两个页面之间“播放一段动画”，而是让对象和状态连续变化。它用于传达状态、提供反馈和指导、建立空间关系，并增强界面生命感。

## 动效准入

写动画前依次判断：

1. **目的**：是否承担即时反馈、状态说明、空间连续性、避免突变、必要解释或低频愉悦？说不清目的时不增加动画。
2. **频率与输入**：高频、键盘驱动或重复操作优先使用系统反馈、即时变化或近乎不可感知的过渡；没有埋点或观察证据时，不虚构每日次数。
3. **功能影响**：用户正在阅读、比较或操作的数据不能为了装饰持续移动；动画不能延迟可操作性、焦点、权限判断或业务结果。
4. **环境**：确认目标平台、输入方式、现有组件和动画能力。优先系统、宿主或现有框架行为；只有任务需要且运行时支持时才自定义。
5. **退出条件**：必须定义完成、取消、中断、反向、路由离开和 Reduce Motion 后的正确状态。

固定时长、弹簧参数和频率阈值只能作为经项目验证的局部令牌，不能当成跨平台规则。

## 先定义状态关系

动画前先写清楚：

| 项目 | 要回答的问题 |
| --- | --- |
| 触发 | 用户或系统做了什么？ |
| 起点 | 哪个对象、位置和状态是来源？ |
| 终点 | 对象最终处于什么业务状态？ |
| 因果 | 为什么是这个对象发生变化？ |
| 反馈 | 操作开始后立即看到什么？ |
| 返回 | 反向操作时回到哪里？ |
| 中断 | 重复输入、拖回或路由变化时怎么办？ |
| 减少动态 | 如何表达同一状态与关系？ |

业务状态是事实来源，动画只是状态变化的表现。不要用动画回调代替业务完成，也不要等待装饰动画结束才更新焦点、权限或数据。

## 连续性与空间记忆

当对象身份连续时，优先让同一元素移动、缩放、裁切、圆角变化、变形或重新排版：

```text
卡片 -> 展开 -> 详情
按钮 -> 扩张 -> 搜索框
迷你播放器 -> 放大重排 -> 完整播放器
```

这种转场解释“从哪里来、去了哪里、两个状态是什么关系”。关闭或返回时尽量回到来源对象和原上下文。只有对象确实相同时才使用共享元素或 Morph；不要把无关元素强行连接。

## 手势驱动与可打断

- 手势过程中视觉状态持续跟随位移、速度和方向。
- 手势结束后的动画从当前视觉位置和速度继续，不跳回预设起点。
- 动画期间保持对有效输入的响应；新输入从当前状态平滑转向新目标。
- 反向手势自然反转，不要求用户等待动画播放完。
- 交互阈值、吸附和取消区域可预测，避免误触。

## 物理感与弹簧

Apple 常用弹簧表达有目标位置、重量、吸附和边界的对象。物理感来自连续速度、加减速、惯性、轻微超调和阻尼的协调，而不是所有东西都弹一下。

- 高频、小距离操作更快、更克制。
- 大距离或结构变化可稍长，但不能阻塞用户。
- 直接操作应保留输入速度，不统一播放固定时长曲线。
- 淡入淡出适合没有明确空间来源的内容或减少动态效果模式。
- 避免无目的循环、夸张回弹、布局抖动和过长入场编排。

优先使用目标平台和现有框架的系统动画、导航转场与成熟 API。Apple 原生平台使用系统能力可获得更一致的交互、可访问性和中断行为；Web 转译时要单独实现这些行为，不能只复制 easing。

浏览器或已确认使用 Web 渲染的界面需要自定义拖动、滑动、惯性、吸附或可打断弹簧时，继续读取 [web-motion.md](web-motion.md)。

## 反馈、声音与触觉

视觉、声音和触觉可以共同确认操作，但强度要匹配信息重要性：

- 轻微按压反馈确认控件已收到输入；
- 触觉适合确认、边界、选择变化或重要结果；
- 声音和触觉不能成为唯一状态信号；
- 高频操作避免每次都使用强反馈；
- 设备或网页不具备对应能力时保持完整视觉路径。

## 减少动态效果

尊重目标平台可用的减少动态效果设置；Web 使用受支持的 `prefers-reduced-motion`，小程序或混合容器先核实宿主能力，不虚构偏好读取 API。减少动态不等于删除状态反馈：

- 减少大幅位移、缩放、景深和视差；
- 使用更短、更少移动的变化或淡化；
- 保留焦点、进度、结果与错误反馈；
- 不能因为跳过动画而漏掉状态收口或可操作性恢复。

## 性能

流畅度属于 Craft。Web 中优先合成友好的 `transform` 和 `opacity`，避免高频交错读写布局、过大的模糊区域和持续 `will-change`。动画实际帧率、输入响应、滚动和低性能设备需要运行态验证；构建成功不能证明动效跟手。
