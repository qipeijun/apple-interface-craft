# Apple-inspired Web 动效实施

仅在 Web 任务需要自定义手势、惯性、吸附、弹簧或复杂状态转场时读取。Apple 原生平台优先系统组件和动画 API；简单淡化、悬停或按压反馈不需要引入动画库。

## 先建立交互契约

实现前写清楚以下事实：

| 项目 | 需要确认 |
| --- | --- |
| 对象 | 用户直接操作的真实对象及其业务状态 |
| 输入 | 触摸、鼠标、触控板、键盘和辅助技术路径 |
| 范围 | 可移动轴、边界、有效目标和滚动竞争关系 |
| 提交 | 哪个条件提交，哪个条件取消或回到起点 |
| 中断 | 动画中再次输入、反向、路由变化和组件卸载时怎么办 |
| 替代 | Reduce Motion、无拖动能力或不支持相关 API 时如何完成任务 |

只有对象确实具有空间、顺序或连续参数时才自定义直接操纵。关键能力必须另有可见控件、键盘或辅助技术入口。

## Pointer Events 生命周期

- 优先复用成熟组件或项目现有手势能力；自定义时使用 Pointer Events 统一处理触摸、鼠标和笔输入。
- 按下后立即给出视觉反馈，但在有效释放、业务条件成立时才提交动作；支持移出取消以及返回有效区域。
- 记录抓取点相对对象的偏移，避免拖动开始时对象中心跳到指针位置。
- 确认拖动意图后使用 `setPointerCapture(pointerId)`，让指针离开元素后仍能连续跟踪；同时处理 `pointerup`、`pointercancel`、`lostpointercapture` 和组件卸载清理。
- 只有明确需要接管的轴才调整 `touch-action`，避免破坏页面滚动、缩放、系统返回手势或辅助技术。
- 多指输入、按钮类型和重复 pointer 必须有明确策略，不能让第二个触点重置当前拖动。

不要复制固定像素阈值作为所有设备的通用手势门槛。优先采用组件库、平台约定或经目标设备验证的项目令牌。

## 速度、投影与吸附

拖动过程中保留一小段带时间戳的位置历史，以一致单位估算释放速度。松手后的行为按以下顺序决定：

1. 根据当前位置、方向和速度估计运动趋势；
2. 在业务允许的吸附点中选择目标；
3. 从当前屏幕值和当前速度继续，而不是从逻辑起点重新播放；
4. 边界外使用连续增大的阻力并提供取消路径，不能用硬停止伪装冻结；
5. 距离接近零、采样不足、输入取消或目标失效时，回到明确的非惯性路径。

投影衰减常数、速度阈值和 Rubber-banding 系数不是 Apple 风格常量。它们受输入设备、尺寸、采样、动画库和产品任务影响，只有来自系统 API、成熟库或目标设备验证时才能固化。

## 动画能力选择

选择项目中成本最低且能正确表达行为的能力：

- 简单属性变化、按压和短暂显隐优先现有 CSS 令牌或过渡；
- 预定时间线且不依赖实时输入时，可使用 CSS Animation 或 Web Animations API；
- 手势驱动、布局连续性、退出动画、速度继承或频繁重定向时，使用项目已有且支持取消、读取当前值和重新定向的成熟动画库；
- 不为一个简单效果新增依赖，也不手写已有可访问组件能可靠处理的 Sheet、Popover、Dialog 或拖放系统。

弹簧 API 的参数名称不能跨库直接换算。以 Motion 为例，当前官方文档区分物理弹簧与时长型弹簧：`stiffness`、`damping`、`mass` 可继承已有速度，而 `duration`、`bounce` 不会继承速度。使用其他库时重新核对其当前官方文档，不凭名称相似推断。

业务状态不能由动画完成回调决定。动画被取消、跳过、反向或 Reduce Motion 生效时，数据、焦点、权限和可操作性仍必须正确收口。

## 属性与性能

- 优先使用合成友好的 `transform` 和 `opacity`，但不要把它们写成绝对禁令；布局、裁切或形变确有语义时，选择能表达关系的属性并测量成本。
- 避免持续的大面积模糊、阴影、滤镜、交错布局读写和长期 `will-change`。
- 同一对象的视觉变化尽量由一个状态源驱动，避免 CSS、组件状态和动画库同时争夺 transform。
- 运行时内容要预留空间，避免动画期间布局跳动和误点。

## 用户偏好

- `prefers-reduced-motion: reduce` 下移除或替换大幅位移、缩放、视差、旋转和弹性超调，但保留必要的状态、焦点和结果反馈。
- `prefers-reduced-transparency: reduce` 下为模糊或半透明层提供更实的背景；使用前核对目标浏览器支持并保证默认样式本身可读。
- `prefers-contrast: more` 与 `forced-colors` 下减少装饰、保证边界和状态清楚；不要把所有非默认偏好都误解成“更高对比”。
- Hover 动效只在设备真实支持 hover 且有精细指针时增强，触摸路径不能依赖 hover。

## 运行态验收

静态代码不能证明手势跟手或动画连续。按任务验证：

- 指针按下、移动、释放、取消和移出后的反馈与提交语义；
- 慢拖、快甩、反向、中断和动画中再次操作；
- 边界、吸附点、滚动竞争、多指和组件卸载；
- Reduce Motion、减少透明度、高对比和键盘等价路径；
- 慢速设备、长列表、复杂背景下的输入延迟、掉帧和布局稳定性；
- 目标手机或触控板上的真实手感，必要时慢放或逐帧检查。

浏览器、设备和性能工具的使用必须遵循项目授权。没有运行态证据时，只能报告实现逻辑和静态风险，不能声称“丝滑”或“符合真机手感”。
