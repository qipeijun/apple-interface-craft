# Apple 无障碍、包容性与责任

Apple 将 accessibility 视为从设计开始就必须考虑的优先事项，将 Responsibility 视为安全、隐私、透明度和信任的一部分。

## 设计包容性体验

WWDC25 的 inclusive app design 强调：理解排除差距、支持多种感官与交互、提供可定制能力、采用 Accessibility API，并持续追踪尚未解决的包容性问题。

设计和实现时检查：

- 信息是否可以通过不止一种感官获得；
- 核心功能是否支持不止一种物理交互；
- 手势是否有可见控件或辅助技术替代；
- 音频提示是否有视觉或触觉等价反馈；
- 颜色是否配合文字、图标、形状或位置表达状态；
- 用户是否可以调整文字、对比、动态、声音或其他关键偏好；
- 是否使用原生语义和 Accessibility API 暴露名称、值、状态、动作与顺序。

不要用模拟障碍或设计者自测代替残障用户参与。没有真实参与证据时，只能说完成了规范或专家检查。

## 视觉与文字

- 支持目标平台承诺的文字大小与布局重排；支持 Dynamic Type 的 Apple 平台使用相应能力，macOS 不套用此 API，Web 检查缩放，小程序核实宿主支持。
- 有意义的界面图标在需要时随文字缩放。
- 保持足够对比度，并在材料、照片、深色模式和高对比设置下复验。
- 不依赖颜色或透明度作为唯一状态信号。
- 不裁切关键文字、按钮和状态；本地化与长文本下仍可用。

## 操作与输入

- 控件尺寸和间距遵循目标平台规范与输入情境；不跨平台套一个数值，也不把 pt、dp、CSS px 和 rpx 等同。
- 常用操作使用简单手势，避免要求特定身体姿势或复杂多指动作。
- 拖放、滑动删除等提供屏幕控件、键盘或辅助技术路径。
- 按目标平台支持任务涉及的辅助技术。Apple 平台可涉及 VoiceOver、Voice Control、Full Keyboard Access 等；其他运行时核实其语义与能力，不能照搬名称即声称支持。
- 焦点顺序与视觉和任务顺序一致；动态内容出现后焦点去向可预测。

## 动态、声音和触觉

- 尊重 Reduce Motion，避免大幅视差、闪烁、突然移动和不必要循环。
- 重要音频信息配合视觉提示；适合时增加触觉，但触觉不作唯一反馈。
- 动态内容需要通过可访问方式说明变化，不能只靠屏幕上的运动让用户理解。

## 隐私与权限

- 只请求产品功能真正需要的数据或设备能力。
- 最好等到用户实际使用相关功能时再请求权限，避免无上下文的启动时弹窗。
- 权限文案清楚说明为什么需要、如何使用以及用户能获得什么。
- 用户拒绝后保持可理解的降级路径；允许在系统或产品设置中修改选择。
- 不把敏感数据暴露在通知、建议、共享设备或公共界面中。
- 不用诱导性按钮、虚假紧迫或隐藏拒绝迫使授权。

## 风险与恢复

对不可逆、高价值或可能伤害用户的操作，提前展示真实对象与后果。风险可避免时先通过默认值、范围限制和预览预防；可逆时优先撤销，避免过度弹窗。安全和隐私要求不能为了界面更流畅而被动画或自动操作掩盖。
