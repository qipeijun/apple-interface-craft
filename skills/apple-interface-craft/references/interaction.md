# Apple 交互与反馈

Apple 式交互的目标是缩短用户意图与结果之间的距离，让对象、状态和后果可见、可预测、可控制。

## 组件交互契约

优化组件前，沿调用方确认当前行为，只补当前任务相关项：

| 维度 | 必须明确的边界 |
| --- | --- |
| 对象与来源 | 操作哪个对象；状态由父级、路由、组件草稿还是服务端拥有 |
| 选择与编辑 | 焦点、选中、激活、临时输入和已提交结果是否不同 |
| 生效时机 | 即时生效、应用或保存；本地确认与服务端成功分别何时发生 |
| 离开语义 | 关闭、遮罩点击、返回、取消分别保留或丢弃什么；焦点回到哪里 |
| 异步结果 | 重复输入、失败、过期结果、离开后返回如何影响当前对象 |
| 等价入口 | 触摸、键盘、指针或辅助技术如何完成同一任务 |

交互问题先检查状态和事件契约，再调整外观。不要为了套用模式新增不存在的自动保存、撤销接口或取消请求能力。控件简单且没有这些状态时，不制造额外流程。

## 熟悉模式与直接操纵

优先支持目标平台用户首先会尝试的标准动作。以下为 Apple 触摸交互示例，迁移时核对宿主惯例：tap 激活或选择、swipe 揭示或移动、drag 移动物体、touch and hold 显示上下文能力、pinch 缩放。自定义手势不能重新定义标准手势，也不能阻断系统返回、滚动或辅助技术。

直接操纵适合对象本身具有空间、尺寸、顺序或连续参数时：

- 拖动时对象持续跟随输入，而不是松手后才变化；
- 缩放、滑块、排序和窗口调整实时显示结果；
- 拖放显示可拖来源、有效目标、接受或拒绝状态和放置预览；
- 松手后继承位移或速度，再按边界、吸附和阻尼收敛；
- 移动、复制和删除的语义与平台惯例一致。

直接操纵不是所有操作的默认答案。关键能力不能只藏在手势中；提供可见控件、键盘或辅助技术等价入口。简单按钮更明确时，不增加拖拽或长按学习成本。

## 控件状态

每个交互控件按任务覆盖必要状态：

- 可用；
- 按下或激活；
- 聚焦、悬停或指针反馈；
- 选中；
- 禁用以及禁用原因；
- 正在处理；
- 成功或失败。

看起来相同的控件应行为相同。不要用颜色作为唯一状态信号，也不要让“禁用”同时承担无权限、数据缺失、请求中和业务不可操作等不同含义。

## 即时反馈

反馈帮助用户理解发生了什么、下一步能做什么、操作结果是什么以及如何避免或纠正错误。

按重要程度选择反馈强度：

- 控件自身的高亮、缩放、状态或内容变化用于即时响应；
- 页面内状态用于普通加载、保存、同步和结果；
- 进度用于持续时间明显的任务；
- alert 只用于需要立即注意且最好可行动的关键问题；
- 声音和触觉用于适合设备与任务的重要确认，不能成为唯一反馈。

用户通常预期普通操作成功，不要为每次成功弹出确认。对重要完成结果可以明确确认；失败应在相关上下文说明问题和恢复动作。

## 进度与等待

- 时长可估计时优先确定进度，并尽可能准确反映真实进展。
- 不可估计时使用不确定进度，但一旦能够估计可切换为确定进度。
- 不伪造平滑进度，不让 90% 长时间停滞而无说明。
- 任务停滞时说明发生了什么以及用户能做什么。
- 可以安全停止时提供取消；取消会丢失进度时说明后果并允许继续。
- 进度消失必须由真实任务状态驱动，不由固定计时器驱动。

## 错误预防与恢复

- 优先设计约束和预览来防止错误，而不是事后堆提示。
- 低风险可逆操作优先撤销，避免频繁确认打断节奏。
- 对意外且不可逆的数据损失，在执行前明确说明对象和后果。
- 错误信息使用自然语言，定位具体问题并给出真实可行的下一步。
- 保留用户输入、选择和上下文，避免失败后重新开始。
- 业务失败、网络失败、无权限、资格不符和系统不可用应分别表达。

## 关键动作检查

对每个关键动作确认可发现性、即时反馈、处理中状态、真实结果、失败恢复，以及非默认输入方式的等价路径。
