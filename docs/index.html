02 / EIGHT DESIGN PRINCIPLES

每一处细节，
都有一个更好的理由。

八项原则是一组取舍工具。把产品目的与使用情境放在一起，找到适合这一次任务的答案。

创造真正的价值Purpose

从用户最在意的任务出发，让每个元素都能解释自己的存在。

把控制权交还用户Agency

知道正在发生什么，能够退出、撤销，并从错误中恢复。

把信任放进设计Responsibility

在需要时解释权限，保护隐私，清楚表达操作的影响。

让已有经验继续有效Familiarity

沿用目标平台熟悉的对象、动作和反馈，降低学习成本。

适应不同使用情境Flexibility

窗口、文字、输入方式发生变化，任务仍然可以继续。

让复杂变得清楚Simplicity

用结构与渐进披露管理复杂度，保留必要的信息和能力。

认真对待每个状态Craft

让体验有人情味Delight

05 / A SHARED WAY OF WORKING

从问题出发，
走到有依据的结果。

CRAFT NOTE / 01

PURPOSE & CONTEXT

先把问题说清楚。

目标不是为界面增加效果，而是让用户更顺利地完成这一次任务。先确认事实，再决定怎么做。

  • 谁在什么情境下，完成什么任务？
  • 现有组件、权限与接口已经约定了什么？
  • 实际运行在浏览器、小程序，还是原生容器？
得到：目的、约束与事实基线。

保留产品自己的性格

沿用品牌、组件库和设计令牌。专业工具可以保持高密度；普通材质可以同样清晰。每次调整都服务于真实任务。

让结论与证据匹配

静态检查说明代码层面的结果；运行态说明实际交互；真机和辅助技术还需要各自验证。不虚构用户研究、性能提升或完成状态。

06 / MAKE IT YOURS

带上你的界面，
从一个真实问题开始。

可以是一张页面、一段组件代码，或一个不够顺手的流程。说明平台与目标，让这个 Skill 帮你把设计决策落到实处。

在开始之前，你可能想知道。

必须做成 Apple 的视觉风格吗？

不需要。明确调用这个 Skill 时，Web、小程序、Android 和其他界面都可以使用它的设计思路。品牌、业务契约与用户明确选择优先；实际行为仍然要符合目标平台。

它如何处理动效与 Liquid Glass？

先明确动效承担的反馈、状态或空间关系，再决定是否添加。高频操作保持克制，减少动态效果时保留完整反馈。Liquid Glass 有具体的平台与材质语义，普通 Web 模糊不能被当作原生材质合规证明。

什么时候设计，什么时候直接修改？

要求设计时输出可评审方案；要求实现或优化时，先核实项目事实，再完成范围内的改动和必要验证。仅审查或诊断时只检查与报告，除非同时授权修改。

如何知道一次优化真的有效？

先定义完成任务所需的行为，再按风险选择验证：相关代码与状态测试、已授权的运行态检查、目标设备与辅助技术体验。没有用户研究或真实性能数据时，不声称转化提升、可用性分数或真机手感已经得到证明。
